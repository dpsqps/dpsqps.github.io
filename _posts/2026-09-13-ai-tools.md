## 오픈AI가 같은 주에 내놓은 두 가지: 하네스를 빌려주고, 지시를 줄이라고 말하다

에이전트를 돌리는 인프라는 오픈AI가 대신 운영해 주겠다는 API가 공개 베타로 풀렸고, 동시에 그 위에 올리는 프롬프트는 오히려 덜어내라는 지침이 나왔다. 만들어 주는 층은 늘리고, 사람이 써넣는 층은 줄이라는 방향이다.

### 오픈AI '에이전트 API' 공개 베타 — 코덱스를 돌리던 하네스를 API 한 번으로

오픈AI가 9월 10일 코딩 에이전트 코덱스(Codex)를 실제로 구동해 온 관리형 하네스를 '에이전트 API'라는 이름으로 모든 개발자에게 공개 베타 개방했다. 세션 오케스트레이션, 컨텍스트 압축, 도구 선택, 하위 에이전트 위임이 API 호출 하나 뒤로 들어간 형태다. 세션이 한도에 가까워지면 이전 내용을 자동으로 압축하고, 도구 검색 기능으로 필요한 도구만 그때그때 불러 토큰 사용량을 줄이며, 복잡한 작업은 메인 에이전트가 독립적인 조각으로 쪼개 하위 에이전트에 넘긴다. 실행 환경은 오픈AI 호스팅 샌드박스, 자체 인프라, 그리고 블락셀·클라우드플레어·데이토나·디지털오션·E2B·모달·오라클·런루프·버셀 등 **9개 파트너** 중에서 고를 수 있다. **API 자체 이용료는 없고** 토큰·도구·컨테이너 시간만 과금한다. 초기 도입 사례로는 시리대(Ciridae)가 평가 점수를 **0.71 → 0.85**로 올리며 지연시간을 **4배** 줄였고, 세이프티킷은 워크플로 이전 후 건당 비용을 **60%** 절감, 하이파는 실패한 에이전트 응답을 **86%** 줄였다고 공개됐다. 다만 데이터 처리는 미국 내로 제한되고 제로 데이터 리텐션(ZDR)은 아직 지원하지 않는다. ### "지시를 덜어내라" — 아스트라용 스킬·AGENTS.md 재점검 지침

같은 주, 오픈AI 코덱스 개발자 경험(DevX) 팀의 에릭 프로방셰가 개발자 블로그에 GPT-6 아스트라를 위한 스킬·프롬프트 재고찰 지침을 올렸다. 핵심 전제는 "더 유능한 모델은 손잡아 주는 일이 덜 필요하다"는 것으로, 지난 1년간 약한 모델을 달래려고 쌓아 올린 스킬 설명·AGENTS.md·태스크 프롬프트의 군더더기가 오히려 아스트라의 성능을 깎는다는 지적이다. 권고는 크게 **3가지**다. ①스킬 설명은 최대한 짧고 트리거가 분명하게("데이터베이스 작업 시 사용" 같은 모호한 표현 대신 "마이그레이션을 추가·변경할 때 사용"), 워크플로가 여러 개면 루트 문서는 하위 문서·스크립트로 안내하는 최소한의 라우터로 두는 '점진적 공개(progressive disclosure)' 구조로 바꿀 것. ②모든 편집 전에 architecture.md·database.md·deployment.md **3개 문서를 상시 로드**시키던 규칙은 "서비스 경계는 architecture.md, 스키마 변경은 database.md, 배포 준비는 deployment.md" 식 조건부 참조로 교체할 것. ③단계마다 승인을 받게 하는 체크리스트 대신 "무엇이 완료인지"를 미리 정의해, 요청한 변경으로 생긴 실패는 승인 없이 고치고 관련 테스트를 다시 돌리도록 허용할 것. 모델을 갈아탈 때 프롬프트 자산도 함께 감사해야 한다는 이야기다.
