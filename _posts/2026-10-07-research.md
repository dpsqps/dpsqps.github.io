## 결과는 쏟아지는데 재현은 누가 하나: 372건의 수학 결과와 '검증'을 다룬 arXiv 세 편

10월 6일 오픈AI가 내부 모델의 수학 결과 372건을 한꺼번에 공개하면서 검증 가능성 논쟁이 다시 커졌다. 같은 시기 arXiv에는 병렬 코딩 에이전트의 조율을 검증하는 벤치마크, 기억을 지우지 못하게 만든 웹 에이전트, 라우팅 신호 평가의 함정을 정리한 논문이 올라왔다.

### 오픈AI, 내부 모델의 수학 결과 372건 공개: "거의 전부 단일 에이전트, 단일 프롬프트"

사이언티픽 아메리칸의 10월 6일 보도에 따르면 오픈AI는 내부 모델이 만든 수학·이론 컴퓨터과학 결과 372건을 깃허브 저장소로 공개했다. 회사는 4차원 카케야 추측 해결, 주요 알고리즘 개선, 리만 가설을 향한 진전 등이 포함됐다고 주장하며, 거의 모든 결과가 에이전트 하나에 프롬프트 하나를 준 것만으로 나왔다고 밝혔다. 다수의 결과는 Lean으로 형식 검증돼 정확성 자체는 사실상 확실하지만, 증명이 새로운 아이디어를 담았는지 기존 기법의 조합인지는 수학자들이 따로 평가해야 한다. MIT의 앤드루 서덜랜드는 모델이 공개돼 재현되기 전까지는 '단일 에이전트 원샷' 주장을 미검증으로 봐야 한다고 지적했고, 토론토대의 대니얼 리트는 답을 알 수 있다면 비공개로 둘 이유가 없다며 공개를 지지했다. 오픈AI 자문 그룹은 모델과 정확한 프롬프트 공개를 권고했으나 회사는 전부 따르지는 않았다. [Scientific American](https://www.scientificamerican.com/article/openai-unleashes-hundreds-more-math-results-upon-a-field-already-in-shock/)

### NP-Bench와 MemMux: 병렬 코딩 에이전트의 충돌 13건을 0건으로, 자원 회수 50%를 100%로

수만유 무쿠(Sumanyu Muku)는 여러 코딩 에이전트를 동시에 돌릴 때 생기는 문제를 다룬 논문 두 편을 10월 5일 제출했다. 첫 논문은 다중 에이전트 조율을 스케줄링 문제로 재정의해, 작업을 겹치지 않는 범위로 나누고 생산자→소비자 그래프 순서로 병합을 미리 정렬하는 플래너를 제안한다. 실제 git 병합으로 평가하는 NP-Bench에서 깨끗한 통합이 9개 시나리오 중 1개에서 9개 전부로 늘었고 병합 충돌은 13건에서 0건이 됐다. 두 번째 논문 MemMux는 1Hz 주기로 에이전트별 메모리 사용을 귀속시키는 로컬 런타임으로, 고정 예산에서 전체 사용량을 7.5GiB·스왑 0으로 유지했고(비관리 도구는 예산의 2배 사용) 종료된 에이전트의 프로세스 트리를 100% 회수했다(기준선 50%). 다만 CPU 오버헤드는 에이전트 10개에서 2.7%로 저자가 정한 목표 2%를 넘었다고 스스로 밝혔다. [arXiv:2610.07261](https://arxiv.org/abs/2610.07261) / [arXiv:2610.07257](https://arxiv.org/abs/2610.07257)

### AMBER: 덮어쓰지 않는 '추가 전용' 메모리로 웹 에이전트 성공률 +4.09%p

친마이 사바디카르(Chinmay Savadikar) 등은 긴 과제를 수행하는 웹 에이전트가 결과 보상만으로 학습할 때 중요한 정보를 메모리에서 지워버리는 문제를 다뤘다. AMBER는 에이전트가 추론·행동·자유 형식 메모리 작성을 함께 학습하되, 메모리는 추가만 가능하고 덮어쓸 수 없다는 규칙으로 정보 보존을 구조적으로 보장한다. WebArena Lite에서 덮어쓰기 방식 메모리 대비 평균 성공률이 4.09%p 높았고, 반복 실행 기준 과제 성공률은 4.8%p 올랐다. 훨씬 비싼 지도학습 데이터로 훈련한 덮어쓰기 기준선과도 같은 수준의 성능을 냈다고 보고했다. 무엇을 기억할지 학습시키는 대신 '잊지 못하게' 제약을 거는 쪽이 더 싸고 안정적일 수 있다는 결과다. [arXiv:2610.07118](https://arxiv.org/abs/2610.07118)

### LLM 라우팅 신호 평가: AUROC 0.871도 '질문 난이도' 기준선과 비교해야 한다

라민 피셰바르(Ramin Pishehvar) 등은 작은 모델이 틀릴 것 같은 질의를 큰 모델로 넘기는 라우팅에서 의미 엔트로피(semantic entropy)를 신호로 쓰는 방식을 3개 벤치마크, 2개 모델 계열에서 평가했다. GSM8K에서는 작은 모델의 오답을 AUROC 0.871로 구분했지만, 합성 벤치마크에서는 단순한 질문 난이도 기준선이 같은 성능을 냈다. 논문은 이를 바탕으로 스스로를 속이는 다섯 가지 경로를 정리한다. 난이도 추정치와 비교하지 않는 것, 성공의 정의가 일관되지 않은 것, 개선 여지가 거의 없는 벤치마크를 쓰는 것, 실시간 샘플링 비용이 큰 모델을 바로 호출하는 비용을 넘을 수 있다는 점 등이다. 비용 절감을 내세운 라우터 제품이 늘어나는 상황에서 '무엇과 비교했는가'를 먼저 물어야 한다는 점을 수치로 보여준다. [arXiv:2610.07354](https://arxiv.org/abs/2610.07354)
